# Implementation Plan: Add Manual Fill-up Fuel Economy Tracking

## Overview
Add support for tracking **actual fuel economy from gas fill-ups** alongside OBD2 trip data. The user will manually record fill-up data in a simple CSV file, which will be automatically processed by the existing refresh workflow and displayed as a second line on the fuel economy chart.

## User Requirements
- **Data format**: Date and pre-calculated MPG (user calculates MPG from gallons/odometer manually)
- **File format**: CSV file (`fillups.csv`)
- **Chart display**: Second line on the same chart as OBD2 data
- **Storage**: Database (for consistency and query efficiency)
- **Auto-processing**: Should be triggered by existing auto-refresh script (no manual dashboard clicks needed)

## Design Decisions

### 1. File Format: `fillups.csv`
Location: `/data/fillups/fillups.csv` (separate from OBD2 uploads to avoid confusion)

**Format:**
```csv
date,mpg,notes
2026-02-15,28.5,Shell station
2026-02-22,27.8,
2026-03-01,29.2,Premium fuel test
```

**Rules:**
- Header row required: `date,mpg,notes`
- `date`: YYYY-MM-DD format
- `mpg`: Decimal value (user-calculated actual fuel economy)
- `notes`: Optional text field
- Empty notes field allowed (but comma still required)
- Lines starting with `#` are comments (ignored)

### 2. Database Schema: New `fillups` Table

**Table definition:**
```sql
CREATE TABLE fillups (
    id INT AUTO_INCREMENT PRIMARY KEY,
    fillup_date DATE NOT NULL,
    mpg_actual DECIMAL(6, 2) NOT NULL,
    notes TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    INDEX idx_fillup_date (fillup_date),
    UNIQUE KEY unique_fillup_date (fillup_date)  -- One fill-up per day max
);
```

**Rationale:**
- `UNIQUE KEY` on `fillup_date`: Prevents duplicate entries for same day
- If user edits CSV and re-runs refresh, UPDATE existing record instead of creating duplicate
- `updated_at`: Track when record was last modified (for debugging)

### 3. Processing Logic: Extend File Monitor

**Modified workflow:**
1. When `/api/refresh` is called (by dashboard button OR auto-refresh script):
   - Process OBD2 CSVs in `/data/csv_uploads/` (existing)
   - **NEW:** Check if `/data/fillups/fillups.csv` exists
   - **NEW:** If fillups.csv exists and modified since last check, re-import all records
   - Use `REPLACE INTO` SQL to update existing records or insert new ones
   - Track last modification time in `processing_logs` table

**Benefits:**
- Existing auto-refresh script automatically processes both OBD2 trips AND fill-up data
- User just edits fillups.csv and waits for next auto-refresh (or manually triggers)
- No separate refresh workflow needed

```python
def scan_folder(self, db: Session) -> Dict:
    """Scan uploads folder for OBD2 CSVs and fillups.csv"""
    results = {
        'obd2_files_scanned': 0,
        'obd2_files_processed': 0,
        'trips_created': 0,
        'fillups_processed': False,      # NEW
        'fillups_updated': 0              # NEW
    }

    # Process OBD2 CSV files (existing logic)
    # ...

    # NEW: Check for fillups.csv
    fillups_csv_path = Path(settings.FILLUPS_FOLDER) / 'fillups.csv'
    if fillups_csv_path.exists():
        fillups_mtime = fillups_csv_path.stat().st_mtime

        # Check if file modified since last import
        last_import = db.query(ProcessingLog).filter(
            ProcessingLog.filename == 'fillups.csv',
            ProcessingLog.status == 'success'
        ).order_by(ProcessingLog.processed_at.desc()).first()

        should_process = (
            last_import is None or
            fillups_mtime > last_import.processed_at.timestamp()
        )

        if should_process:
            try:
                processor = FillupProcessor(str(fillups_csv_path))
                sync_result = processor.sync_to_database(db)

                results['fillups_processed'] = True
                results['fillups_updated'] = sync_result['records_added'] + sync_result['records_updated']

                # Log success
                log = ProcessingLog(
                    filename='fillups.csv',
                    status='success',
                    message=f"Imported {sync_result['records_added']} new, updated {sync_result['records_updated']} existing fill-ups",
                    details=json.dumps(sync_result)
                )
                db.add(log)
                db.commit()

            except Exception as e:
                # Log error
                log = ProcessingLog(
                    filename='fillups.csv',
                    status='error',
                    message=f"Failed to process fillups.csv: {str(e)}"
                )
                db.add(log)
                db.commit()

    return results
```

```python
@app.get("/api/fillups", response_model=schemas.FillupsListResponse)
async def get_fillups(
    limit: int = Query(50, ge=1, le=200),
    offset: int = Query(0, ge=0),
    days: Optional[int] = Query(None, ge=1),
    db: Session = Depends(get_db)
):
    """
    Get fill-up records

    Query params:
    - limit: Max records to return (default 50, max 200)
    - offset: Pagination offset
    - days: Filter to last N days (optional)
    """
    try:
        query = db.query(Fillup)

        # Filter by date range if specified
        if days:
            cutoff_date = datetime.now().date() - timedelta(days=days)
            query = query.filter(Fillup.fillup_date >= cutoff_date)

        # Get total count
        total = query.count()

        # Apply pagination and sort
        fillups = query.order_by(Fillup.fillup_date.desc()).offset(offset).limit(limit).all()

        return schemas.FillupsListResponse(fillups=fillups, total=total)

    except Exception as e:
        logger.error(f"Error fetching fillups: {e}")
        raise HTTPException(status_code=500, detail="Failed to fetch fill-up data")
```

```python
@app.get("/api/stats", response_model=schemas.StatsResponse)
async def get_stats(
    days: int = Query(28, ge=1, le=365),
    db: Session = Depends(get_db)
):
    # ... existing trip processing logic ...

    # NEW: Calculate fill-up statistics
    fillups_query = db.query(Fillup).filter(
        and_(
            Fillup.fillup_date >= start_date,
            Fillup.fillup_date <= end_date
        )
    ).order_by(Fillup.fillup_date.desc())

    fillups = fillups_query.all()

    actual_fillups = schemas.ActualFillupStats()

    if fillups:
        fillup_values = [float(f.mpg_actual) for f in fillups]

        # Split into current vs previous week
        week_ago = end_date - timedelta(days=7)
        two_weeks_ago = end_date - timedelta(days=14)

        current_week_fillups = [f for f in fillups if f.fillup_date > week_ago]
        previous_week_fillups = [f for f in fillups if two_weeks_ago < f.fillup_date <= week_ago]

        if current_week_fillups:
            current_mpg = [float(f.mpg_actual) for f in current_week_fillups]
            actual_fillups.current_week_avg = round(sum(current_mpg) / len(current_mpg), 2)

        if previous_week_fillups:
            prev_mpg = [float(f.mpg_actual) for f in previous_week_fillups]
            actual_fillups.previous_week_avg = round(sum(prev_mpg) / len(prev_mpg), 2)

        # Calculate trend
        if actual_fillups.current_week_avg and actual_fillups.previous_week_avg:
            change = ((actual_fillups.current_week_avg - actual_fillups.previous_week_avg) /
                      actual_fillups.previous_week_avg * 100)
            actual_fillups.change_percent = round(change, 2)

            if abs(change) < 2:
                actual_fillups.trend = "stable"
            elif change > 0:
                actual_fillups.trend = "improving"
            else:
                actual_fillups.trend = "declining"

        # Last fill-up details
        latest = fillups[0]  # Already sorted desc
        actual_fillups.last_fillup_date = latest.fillup_date
        actual_fillups.last_fillup_mpg = float(latest.mpg_actual)

    return schemas.StatsResponse(
        # ... existing fields ...
        actual_fillups=actual_fillups      # NEW
    )
```

```javascript
function updateChart(trips, fillups) {
    const ctx = document.getElementById('fuelEconomyChart').getContext('2d');

    // Prepare OBD2 trip data
    const tripsSorted = [...trips].reverse();
    const tripLabels = tripsSorted.map(t => t.trip_date);
    const tripData = tripsSorted.map(t => t.avg_fuel_economy_mpg);

    // Prepare fill-up data
    const fillupsSorted = [...fillups].reverse();
    const fillupLabels = fillupsSorted.map(f => f.fillup_date);
    const fillupData = fillupsSorted.map(f => f.mpg_actual);

    // Combine all unique dates for x-axis (sorted)
    const allDates = [...new Set([...tripLabels, ...fillupLabels])].sort();

    // Map data to common x-axis
    const tripDataMapped = allDates.map(date => {
        const trip = tripsSorted.find(t => t.trip_date === date);
        return trip ? trip.avg_fuel_economy_mpg : null;
    });

    const fillupDataMapped = allDates.map(date => {
        const fillup = fillupsSorted.find(f => f.fillup_date === date);
        return fillup ? fillup.mpg_actual : null;
    });

    // Destroy existing chart if present
    if (window.chart) {
        window.chart.destroy();
    }

    // Create new chart with two datasets
    window.chart = new Chart(ctx, {
        type: 'line',
        data: {
            labels: allDates,

                {
                    label: 'OBD2 Trips',
```

## Edge Cases & Error Handling

### 1. Invalid CSV Format
**Scenario:** User forgets header row or uses wrong format

**Handling:**
- Validate header row matches `date,mpg,notes`
- Log error to `processing_logs` table
- Return error in `/api/refresh` response
- Do not crash; skip fillup processing and continue with OBD2 files

### 2. Invalid Date Format
**Scenario:** User enters `02/15/2026` instead of `2026-02-15`

**Handling:**
- Parse date with pandas, catch `ValueError`
- Log specific row number and error message
- Skip invalid row, continue processing valid rows

### 3. Missing fillups.csv
**Scenario:** User hasn't created the file yet

**Handling:**
- Check if file exists before attempting to read
- If missing, skip fillup processing silently
- Dashboard shows "No fill-ups recorded" in summary card

### 4. Empty fillups.csv
**Scenario:** File exists but has only header row

**Handling:**
- Parse successfully, find 0 records
- Log info message: "No fill-ups to import"
- Dashboard shows empty dataset (green line not rendered)

### 5. Unrealistic MPG Values
**Scenario:** User enters `150.5` or `-5.0`

**Handling:**
- Validate range: 5-60 MPG (wider than OBD2 validation for flexibility)
- Log warning for values outside range
- Still store value (user may have special reason), but flag in logs

### 6. File Modification During Read
**Scenario:** User edits fillups.csv while system is reading it

**Handling:**
- Use file locking or catch `IOError`
- If read fails, log error and retry on next refresh
- Do not delete or corrupt file
